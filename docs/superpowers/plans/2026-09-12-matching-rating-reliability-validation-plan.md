## 1. 范围与效率约束

- 2026-09-13 用户明确要求继续执行并授权必要操作，包含本任务 Beckon 修复迁移部署、指定 TestOps 账号夹具写入与精确恢复，以及必要 API/Simulator 验证；不扩展到无关账号、Auth/Storage 删除、依赖或上架范围。
- 本地机器和模拟器足够；不加入真机、签名、上架、APNs、时区设置迁移或旧历史文档收口。
- 保留请求优先闭环、所有合法候选可发现、显式偏好、RLS、版本化成交、时间与容量约束。低分不得变成禁止报价/成交；公开星级不变成内部专业适配分。
- 无评价不等于差评；中性 50 分不等于 50% 成功率。独立账号不等于独立真人；未履约、未评价、取消不能直接充当专业负面证据。
- 按完整工作包推进；只维护 Current State、此计划复选框和执行时的一份验收摘要。原始运行数据放现有忽略目录，不追加多份记忆、日报或平行清单。
- 不重跑未受影响的 T-390 全矩阵。日常只运行受影响测试；业务代码变更后在最终集成节点运行一次必要完整回归。单纯数据分析不触发 iOS 编译或全量测试。
- 工具预算为一个窄离线评估入口及其单测，加现有 TestOps 的必要适配；不做通用数据平台、自动调参框架、生产画像或多版本在线服务。参数实验先离线，不以发布替代比较。
- 判定可以是通过、不通过、未优于基线或证据不足。失败后修复明确缺陷并复验，不通过扩充样本、挑选指标或无限调参强行得到正结论。

## 4. RV-01：冻结验证协议与独立样本

- [x] **确认起点与复用范围。** 对照第 2 节，记录需复验的差异和唯一证据入口。当前排序已全局启用，而旧 `pagingLive()` 断言 `enabled=false` 且会修改验证名单；执行前必须适配，不能为跑旧脚本关闭当前算法。
- [ ] **建立样本而非凑测试数量。** 首批目标 60 个决策快照，顾客报价选择/美容师需求选择各 30 个；每侧约 10 个开发、20 个保留评估。一个快照是一个角色在一个时点面对的完整合法候选集合，不是一次 RPC，也不是一次真实履约。少于目标时记录实际数量，不用合成数据补足“真人”数量。
- [ ] **覆盖边缘但不做笛卡尔积。** 以配对样本覆盖猫/犬、固定/自定义、未知信息/需评估、毛结/敏感护理、无/少/多评价、近期负面、多宠多单、多报价、距离/价格/时间取舍、相邻可约时段。标签可重叠；每个风险至少一个可追溯样本，不能把风险定向样本比例当作市场占比。
- [ ] **冻结比较输入与拆分。** 保存 `case_id`、`source_kind`、`source_group`、角色、明确偏好、`as_of`、来源/revision、合法全集、服务时点、评分版本及实际排序。`source_kind` 只能为真实脱敏资料、受控夹具或合成反例；真实交易结果只能在后续结果区出现。相同请求、关联顾客及近似复制案例不得跨开发/保留集；美容师侧的重复决策按来源美容师聚类。同一历史资料只使用该时点已知信息，禁止未来评价泄漏。
- [ ] **确定盲评与基线。** 美容师端由至少 2 位有实际经验的美容师独立评审，分歧才请第 3 位；顾客端优先由需求本人或明确给定偏好的目标顾客评审，不能由美容师或模型替代。隐藏算法名、分数和原排名，随机展示顺序；只展示该角色依法可见的事实，缺失保留缺失。主观适合度与硬资格标签分开。

基线冻结：美容师为距离、最新；顾客为距离、价格、最早可约。当前综合排序单独比较；显式选择某一排序模式的用户只验证该模式契约，不能用综合分覆盖意图。所有版本保持相同资格/状态分组、数据和确定性并列顺序，先全量排序再取 Top-k；顾客候选只能是已收到且当前可选择的有效报价。

盲评标签统一为 `0=不接受`、`1=可接受`、`2=优先选择`、`null=信息不足无法判断`，并记简短原因；不能因“需评估”自动标 0。为减少人工量，只评所有冻结比较方案 Top-5 的并集，再加入两个可用的随机尾部候选作遗漏诊断，其中有合格新人时包含一个。保留原始评审结果与分歧，不强行达成共识；未全量标注不能宣称人工召回率为 100%。

运行清单在揭示保留集标签前冻结：版本、样本/拆分哈希、各侧主比较基线、指标/容差、随机种子、数据排除条件和评估次数。主基线只在开发集选一次，每侧选主指标最好的简单排序，并保留其余结果；无开发标签则预设距离为主基线，不用保留集挑赢家。

## 5. RV-02：工程缺口与浏览稳定性

- [x] **先测试运行安全边界。** 新 run ID 使用 `TESTOPS-T391-` 前缀；门禁仍要求显式 `--execute` 和本任务远程写授权。先用本地行为测试证明非法前缀/未授权拒绝、匹配专用备份与恢复分支均覆盖新前缀、已启用配置不被关闭。初始开关/名单不因测试改动；只使用指定测试账号和精确归属夹具，不新建账号、删除 Auth/Storage 或写真实用户数据。
- [x] **复用主闭环，集中补差异。** 双模拟器分别承担顾客与美容师；并发由多个真实认证身份经现有 API 发起。以一组共享夹具串行覆盖多需求、多报价、并发接单、取消/改期释放后重新发现、评价更新、过期提交、失败重试。缺陷反例保留 request/operation ID、版本、响应和时间，不批量重复 43 项不变回归。SQL 回滚压力、真实角色 HTTP、UI 行为分别标记，不互相冒充。
- [x] **实施固定节奏分页对照。** 美容师侧沿用 26 个需求、每页 6 项、5 页；顾客侧用现有两位测试美容师的有效报价，经 RPC 设置每页 1 项验证两页，不为造规模新增账号。HTTP 分页缩小 page limit 不代表正式 UI 已产生分页，UI 必须按实际列表另验刷新/过期动作；未覆盖的大报价池明确列为规模边界。每种负载每侧 10 次完整浏览，页间等待 1 秒和 5 秒各 5 次；变更相位均匀错开，所有版本复用相同事件时间表。负载为不变、无关对象每 10 秒变更、相关软证据每 60 秒/10 秒变更，以及单次报价撤回/时段占用等硬变化。先测两种不应打断的负载，发现普遍失败即定位，修正后继续，不完成无意义的全表失败运行。
- [x] **分开计数并核验恢复。** 记录首次浏览完成率、每会话刷新次数、重复/遗漏、可报价/可接受成功率、读取 P95、实际变更次数及被变更影响的会话数。中断后停止追加、不重复自动重试、不丢已载入内容；停止变更后首次手动刷新应完成全集浏览。硬变化须及时撤销旧可操作性，提交仍由权威规则拒绝；保留卡片不等于保留旧资格。DEBUG 注入失败只证明对应故障模型，不能称作真实断网实验。
- [x] **按有限反例处置。** 同一候选集重复/遗漏、无关变化触发全局失效、过期错误成交、双重预约或越权属于必修错误；记录最小失败测试后窄修复。高频相关更新导致主动中断先归浏览局限，不能未经测量直接建设持久快照服务。若改游标或软更新策略，保持硬资格即时校验、全局可发现和旧游标隔离，明确取舍后只复验影响范围。

本轮预设体验预算，不是宣称现有实测结果：不变/无关变化的 10 次浏览全部完整；相关软变更每 60 秒时至少 9/10 首次完整，每 10 秒时至少 8/10 首次完整；所有中断在变更停止后一次刷新恢复。10 次只用于可复现的工程筛查，不能估计真实人群可靠率。10 秒预算未达标即记录局限/待修复，不调慢用户翻页、减少候选或降低目标来通过；它不自动推翻 T-390 当时按原标准的验收。

读取性能沿用原预算：SQL P95 <=1500ms，角色 HTTP P95 <=2500ms；每侧/比较版本各 30 次，首读另列，不跨冷暖样本平均 P95，不把两报价与 26 需求的耗时当同规模比较。静态硬资格夹具的允许/排除集合与独立业务事实核对，要求无错误放行、无合法候选丢失；动态集合必须以对应 revision 比较，不能要求变化前后集合完全相同。

## 6. RV-03：独立质量、评分边界与有限校准

- [x] **先验证评估器，再读真人结论。** 离线入口只接收快照、排序 ID 和盲评标签，输出逐例差值、分层分母、未判定原因与汇总；不调用生产公式生成主观标签。拒绝重复 ID、候选不一致、时点/版本不一致、跨拆分泄漏和缺失 Top-k 标签。用以下手算样例及全空、少于 3 项、未知标签、重复顾客分组测试定义结果，不新建统计框架。2026-09-13 本地结果与其他步骤的部分证据见[唯一验收摘要](../../04_ios/testops/T-391_MATCHING_RATING_VALIDATION.md)；默认不读取保留集，须显式传入 `--split holdout`。
- [ ] **做同池配对盲评比较。** 每侧独立报告 `Acceptable@3` 主指标和 `Hit@3` 次指标，并列出 Top-1 明显违背明确偏好的案例。相关性标签 >=1 为可接受，`k=min(3, 合法候选数)`；无候选不进入排序质量分母，但单列供需覆盖问题。`null` 不能按 0 处理：该例不参与主配对结果，列入缺失/最好最坏边界，开发或保留集任一侧不可判定超过 10% 时不下优劣结论。
- [x] **检查反馈、稀疏与攻击边界。** 复用公开整数均分、相同账号总影响受限、冻结服务上下文的既有证据；补一组跨账号协同高分/低分压力、近期负面与大量旧好评、选择性缺项、标签伪造、半径修改、自报作品和无关物种专业 F 转移反例。跨物种总体 Q 的合法变化不能误判成 F 泄漏；多真实独立账号与伪装账号无法靠 ID 区分时如实列为能力边界，不增设 KYC/风控平台。
- [x] **单因素测敏感性。** 固定快照，半衰期试 90/180/360 天，平滑强度试 2.5/5/10，距离尺度试 2.5/5/10 英里；每次只变一个参数。平滑强度为 c 时保持 `F=50+50*(P-N)/(P+N+c)`、`Q=100*(c/2+sum(w*x))/(c+sum(w))`，无证据仍为 50，不能只改分母。美容师 F 权重试 0.60/0.70/0.80，差额由 D 承担；顾客 F 试 0.50/0.60/0.70，Q 相应为 0.35/0.25/0.15，D 保持 0.15。每侧最多 8 个非默认单因素版本，不组合网格。记录 Top-3 集合变化和跨 2 分桶边界，近分并列互换不自动当缺陷；任何硬资格变化、分数越界、半径或自报导致不应发生的得分变化必须定位。
- [ ] **最多选一次替代方案。** 只有开发集反例指向明确机制时才形成最多 2 个候选配置，在开发集比较后选 0 或 1 个，冻结版本再开保留集。保留集仅做一次确认；不佳或不确定则保留当前方案并记录原因，不在同一保留集上继续调参。简单排序更好可以成为结论，不要求保住现有综合算法。改变参数只在离线进行，未经采用和验证不发布。

新增评估入口的最小接口与手算验收契约：

```javascript
// scripts/test-t391-matching-quality.mjs exports this pure function.
// Each ordered ID is unique and belongs to the same complete candidate set.
evaluateTop3(["g1", "g2", "g3"], {g1: 2, g2: 0, g3: 1});
// {status: "ok", k: 3, acceptableAt3: 2 / 3, hitAt3: 1}
evaluateTop3(["g1", "g2"], {g1: 2, g2: null});
// {status: "insufficient", reason: "unknown_label"}; no numeric metric.
evaluateTop3([], {});
// {status: "insufficient", reason: "empty_pool"}; not a zero-quality case.
```

执行时的离线命令契约，`RUN_DIR` 指向本次已生成的脱敏材料目录，不是待安装服务：

```bash
node --test tests/matching-quality.test.mjs
node scripts/test-t391-matching-quality.mjs --input "$RUN_DIR/decision-snapshots.json" --labels "$RUN_DIR/blind-labels.json" --out "$RUN_DIR/quality-results.json"
```

评估文件必须记录每个候选的真实角色可见事实、独立硬资格标签及来源、各方案完整排序和盲评理由；离线脚本不得仅凭 ID 推导这些事实。算术差分对照真实 SQL/RPC 输出，人工比较对照独立标签，这两类独立性分别证明。

结论规则：先逐例配对，再按角色/来源组汇总；不能将同一顾客反复下单、同一请求多报价或多个评审标签当成独立样本。来源组足够时使用固定种子、2000 次按来源组重采样的 95% 区间；任一侧保留集独立组少于 20 时只给描述性结果。小型固定评审组的区间仅反映当前评审口径下的样本变化，不代表所有顾客/美容师。

预设主指标容差为 5 个百分点：相对冻结主基线，区间下界 >=-5pp 可称本样本非劣；点提升 >=5pp 且下界 >0 才称本样本有优势；上界 <-5pp 为明确劣势；其他为证据不足。容差是本轮决策标准，不是统计定律，不能看结果后调整。猫/犬、固定/自定义、稀疏/充分证据分别报分母和差值；样本不足不宣称分组无损。新人仅比较条件相同的合法展示机会，不要求与资深者强行等量曝光。

## 7. RV-04：真人行为与最终结论

- [ ] **完成小规模真人选择验证。** 首批 5 位目标顾客、2 位实际美容师，各完成 3 个与其身份/偏好对应的操作任务；这是可用性试验，不是交易效果样本量保证。可在两台模拟器轮流使用独立账号/会话，美容师可处理多单、顾客可发多需求。任务顺序错开、同一案例不向同一人连续展示多个排序，先记录选择理由，再揭示分数；一个排序方案下的行为不能伪装成随机对照结果。
- [ ] **记录最小行为与结果。** 由现有 API 时间戳、UI 测试日志及研究记录还原实际展示位置、明确模式、有效报价到达、查看/选择、提交成败、放弃和理由。只加能回答当前问题的 DEBUG/研究记录，不建设常驻埋点。任务耗时与分页重启按人/任务报告，不把可接受标签或点击视为已完成服务。
- [ ] **审查分数解释是否造成误解。** 询问参与者对无评价、需评估、负面专业反馈、公开星级和综合排序的理解，尤其确认是否把 50 分当成成功概率、把星级当成所有服务能力。记录原话的脱敏摘要与对应页面；同类误解归并成一个问题，不为每位参与者建立独立修复任务。
- [ ] **补齐可获得的真实结果并明确缺口。** 仅当参与者确有真实预约/美容服务及资料授权时，观察下面的成熟窗口指标；没有真实履约不得生成“真实效果通过”。本地研究不要求为验收安排虚假服务，也不自动开展获客或大规模线上实验。
- [x] **收口问题与必要修复。** 每个问题只保留严重性、反例、影响层、最小责任文件、建议和验收证据。授权实施范围内的确定性规则/权限/数据归因错误先修复；排序权重、偏好冲突、多人账号风险等产品取舍先提交证据，不自动更换规则或扩建风控。修复遵循失败测试 -> 最小改动 -> 受影响复验；新版本使哪些证据失效就重跑哪些证据。
- [x] **验证恢复并交付一份摘要。** 精确恢复测试对象和业务字段，保留合法递增 revision，不倒退时间戳以复活旧报价；私有上下文、投影、候选、队列及通知等残留按捕获归属核验。关闭测试故障注入，确认全局开关/名单未被改变。摘要分别给出工程正确性、浏览体验、独立排序质量、真人理解/选择、实际服务效果、抗操纵边界，不用单一“可靠率”混合。

真实结果指标口径：

| 指标 | 分母与观察边界 |
|---|---|
| 首个有效报价等待时间 | 从真实发布到首个有效报价；未收到报价单列无报价比例及已观察时长，不从均值中悄悄删除。到请求到期才判本窗口无报价 |
| 有效报价覆盖率 | 已到观察截止的真实请求中，截止前收到至少一个有效报价的比例；主动取消与自然到期分别列出 |
| 报价接受率 | 请求级至少接受一个报价 / 至少收到一个有效报价的成熟请求；不是接受报价数 / 全部报价数 |
| 预约完成率 | 曾确认且已过最终计划服务结束 7 天的预约，取消仍保留最后有效服务时点并计入分母；完成、取消、未履约分别列出，改期尚未成熟另列，不能只保留成功订单 |
| 不适配与评价 | 明确因需求/能力不适配发生的取消、改期、服务反馈及其证据；未评价和原因不明保持未知，不能作负面专业证据 |

7 天是本轮研究的固定观察窗口，不修改业务履约规则。若发生改期，保留原入组记录及新服务时点，未成熟单独报告，不让改期使失败样本消失。所有改善判断须考虑选择/位置偏差；真实业务样本量根据基线、最小有意义改善和独立供需组决定，不能以 50/60 个案例或少量服务宣称统计可靠。

真实市场因果提升只有在具备足够独立供需与实际服务数据时才能验证。共享美容师时段会导致组间干扰，不能简单按顾客随机 A/B 就声称独立；届时需单独确定区域/供需分组或时间段交替及跨段预约的残留影响。本计划不预建该平台，也不把上架和扩大市场作为本地完成条件。[Airbnb 双边市场研究](https://airbnb.tech/wp-content/uploads/sites/19/2024/12/Understanding-Guest-Preferences-and-Optimizing-.pdf)

- **资料门槛一次提出：** 执行 RV-01 时列出所需脱敏真实需求/有效报价资料、独立评审和参与者；只在确实缺少不可替代资料时向用户提一个具体请求。能自主完成的部分继续执行，禁止反复索要相同输入或用合成数据暗中替换。
- **完成不等于通过：** 一次完整研究可得出不可靠或未优于基线，报告失败即有价值；不把验证任务变成无限算法优化。必要整改有确定范围与单独验收，未采纳的产品优化不成为新增前置条件。
- **外部依赖如实保留：** 没有真人资料/评审时，RV-03 的盲评和 RV-04 的真人步骤保持未完成；可交付已完成的本地子阶段，但整体不标记全部验证完成。实际服务/大规模因果效果是条件性证据，不阻止本地研究收口，也始终不能被标成已通过。
- **不反复开保留集：** 首轮保留集结论后不继续搜索参数；未决问题写出需要的新证据。固定负载失败经确认后不重复跑相同失败；先有相关修正或新诊断证据再复验。
- **验证命令按变更触发：** 仅文档运行 `node scripts/context-hygiene-check.mjs --full` 和 diff 检查；离线评估运行第 6 节单测；评分/刷新改动运行对应 `node --test tests/migrations/<受影响文件>.test.mjs` 及授权真实负例/恢复。Swift 编译改动运行 `./scripts/ios-build.sh`，交互改动增加相应 Simulator 证据；业务集成变更最终运行 `./scripts/preflight.sh` 与 `./scripts/ios-test.sh`，未变证据复用。失败、跳过与未执行分开报告。
- **交付与安全：** 保留用户既有脏文档/归档与凭据，仅暂存本任务明确文件。文档制作完成可按现有授权提交文档；执行完成提交须以采用目标验收为界，不自动部署参数、不做检查点提交、PR 或分支整理。
