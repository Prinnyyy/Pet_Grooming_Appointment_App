## 重点检验场景

1. **多宠多任务不等于同时可成交。** R01-A 占用 G01 的 09:00-10:45，R02-A 占用 10:00-11:15。报价时两份可独立提出；任一成交后，另一份原时段必须重新评估。R01-B 与 R02-B 则在 15:00 的占用边界衔接，可顺序成交。
2. **服务结束不等于资源释放。** R12-A 服务 09:00-10:30，加 15 分钟清洁到 10:45，R17-A 恰在 10:45 开始。用于检验半开区间边界，不凭空加入额外占用。
3. **美容师给不同顾客报价也共享容量。** G12 的 R05-B 与 R13-B 在 9/18 的占用分别为 12:30-16:15、14:15-17:00。两份不能按原样都被接受。移动缓冲只是场景预留，不能声称已验证真实路况。
4. **整体高分不能替代相关经验。** R12 对比 G07 的 4.9/204（猫仅 6 条）与 G09 的 4.7/75（全为猫）；不能凭总体星级断言谁更适合。R03/R22 反过来检验猫经验能否被误当成犬护理优势。
5. **没有评价不等于差；少量高分不等于稳定。** G11 为零评价，G12 只有 9 条。不能伪造差评惩罚新人，也不能从少量 4.9 推断高成功概率。
6. **尊重顾客明确选择。** R06 明确按价格排列：G11 $55 在前，再是 G06 $60，两个 $75 不应挤到更低价之前；同价内部顺序交由现有确定性规则。老客偏好、安静、香氛和造型均不是新增的自动偏好权重。
7. **没成交可以是合理结果。** R20/R21 价格超出顾客预算，顾客可以全部拒绝；R15/R24 没有有效报价，不能解释成服务质量为零或补造候选。R23 过期/撤回报价只属历史，不占当前 Top3。

不提供人工编造的“必选赢家”。上述是可解释的交易/资格预期，不是模拟真人主观打分。

## 使用与验证边界

JSON 是**源场景数据**，不是直接可发给 RPC 的 payload，也不是现有质量评估器的冻结快照。缺少的真实 actor/service/address UUID、地理坐标、条款 revision 和服务端资格/排序结果不能靠假值补齐。

后续如做受控回放，应按现有授权和 TestOps 隔离/恢复方式映射测试账号与服务，所有关联时间统一平移，正常发布和报价，保存真实返回值。资料来源仍为 `synthetic` 或明确标注合成来源的 `controlled_fixture`，不会因为走过 API 就变成真实市场需求。不得将同家庭的 R01/R02、R12/R17 拆成独立真人证据。
