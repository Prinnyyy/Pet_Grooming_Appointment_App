## 1. 1.0 完成定义（Definition of Done）

同时满足以下全部条件，方可宣布 1.0：

1. **审核合规**：账号删除、`PrivacyInfo.xcprivacy`、隐私政策与支持页齐备（提审生死线）。
2. **无半成品交互**：Groomer Offers 能力真实落地（当前 `.offers` tab 被整体隐藏、无报价追踪界面）、无假按钮（通知铃铛 `notificationAction: {}`）、无点了无响应的入口。
3. **市场闭环有时效性**：4 类关键事件（新匹配、新报价、报价被接受、新消息/取消）有 APNs 推送；聊天前台实时。
4. **状态机自洽**：过期请求后台真实转换并在双端正确消失/标记；新激活美容师可匹配到存量开放请求；取消后有再发布路径。
5. **质量达标**：≥300 个 Swift 单测全绿（含边缘用例）；TestOps 远程回归含过期/补匹配/容量边界场景；核心旅程 UI 测试通过；崩溃上报接入；TestFlight 公测 ≥1 周无 P0/P1。
6. **可追溯出包**：基线分支与 `main` 完成对账合并，`v1.0.0` tag 自主干出包。
7. **边界不破**：Open Request -> Groomer Offer -> Customer Confirmation -> Booking 模型不变；不引入公开目录/直接预订/ML 推荐；SwiftUI 不直连 Supabase；远程写入逐任务显式授权。

**明确不进 1.0：** 支付/托管、订阅、公开美容师目录、直接时段预订、地图优先、AI/ML 推荐、多宠物请求、收藏夹、聊天附件/已读回执、审核/纠纷、请求编辑、Admin 后台、社交登录。

### 6.2 边缘用例清单（T-168 执行基准）

**时间与时区（当前最薄弱层）**
- 向导时间预设在临近午夜选"今天"的跨天行为；设备时区 ≠ 服务地时区的持久化/回显一致性；DST 切换日时间窗仍满足 start < end。
- 预约重叠边界：首尾相接（end_a == start_b）判定为**不冲突**（与排他约束语义一致）。
- 可用性窗口边界：恰好落在美容师可用窗口起点/终点的请求时间；休假窗口首日/末日。
- 日容量边界：同日第 N（容量上限）个预约成功、第 N+1 个被拒。
- 48 小时过期边界：恰好 48:00:00；报价 proposed range 在提交瞬间刚好过期。

**字符串与输入**
- 空、纯空白、trim 语义：昵称、宠物名、服务标题、评价内容、聊天消息、街道地址。
- 超长输入：报价留言/评价内容上限 ±1 三点测试。
- Emoji、组合字符、CJK、RTL 在名称/消息/地址中的处理；地址自动填充结果为空/单条/多条的选择行为。
- 聊天纯空白拒发；发送失败重试不重复。

**数值边界**
- 报价价格：0、负数、上下限、上限 +0.01、超两位小数、非数字。
- 评分 0/1/5/6；三条开放请求限制第 3/4 条；照片快照第 20/21 张；服务半径 clamp 上下界外（含 TestOps 已发现的 15 英里教训回归）。
- 体重→尺寸带映射的边界体重值（含尺寸带端点与 T-104 服务尺寸带匹配）。

**集合与状态**
- 空列表全套（无宠物/匹配/报价/预约/会话/作品集/可用窗口）。
- 报价 pending 与 history 分组空/混合展示；证据理由文本缺失时的降级展示。
- 重复操作幂等：重复取消/完成/接受；他端已取消/过期后的动作失败恢复（回滚 + 提示 + 刷新）。

**权限与会话**
- 登出/切换账号后各 Store 清理无残留；本地照片/资料快照缓存的账号隔离。
- RLS 拒绝映射为可理解文案；customer 会话调 groomer 动作路径的前置拦截。

**新功能同步覆盖（随 M1~M3 红/绿交付）**
- T-152：报价列表分组与状态徽标。T-154：过期后双端列表过滤。T-155：补匹配后 feed 出现且证据理由完整。T-156：已读落库跨 Store 实例可见。T-157：device token 登录注册/登出注销。T-161：删除后本地会话与缓存清空。
